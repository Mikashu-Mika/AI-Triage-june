# ตรวจแชตที่ ingest เข้ามา (`scripts/checkIngest.js`)

ใช้ระหว่างทดสอบการเชื่อมต่อกับระบบลูกค้า เช่น OneBoxx เพื่อดูว่าแชตเข้ามาครบไหม และ AI วิเคราะห์เสร็จหรือยัง
สคริปต์**อ่านข้อมูลอย่างเดียว** ไม่แก้อะไรในฐานข้อมูล และไม่พิมพ์บทสนทนาหรือ credentials ออกมา

## วิธีรัน

รันในโฟลเดอร์ repo บอต (ต้องมีไฟล์ `.env` ที่ตั้ง `SUPABASE_URL` และ `SUPABASE_SERVICE_ROLE_KEY` แล้ว)

```bash
node scripts/checkIngest.js --company "<ชื่อบริษัท | company id | client_id>" --since 2h
```

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `--company` | (ต้องใส่) | ชื่อบริษัทแบบตรงทุกตัวอักษร, company id หรือ client_id |
| `--since` | `24h` | ดูย้อนหลังเท่าไร เช่น `30m`, `2h`, `1d` หรือเวลาเริ่ม เช่น `2026-11-27T09:00+07:00` |
| `--stuck` | `10` | `pending` นานกี่นาทีจึงนับว่าค้าง |
| `--json` | - | แสดงผลเป็น JSON (ไม่ตัดรายการ) |

## อ่านผลยังไง

| หัวข้อ | ความหมาย | ถ้ามีรายการ ควรทำอะไร |
|---|---|---|
| Chats received | จำนวนแชตใหม่ในช่วงเวลา แยกตามสถานะ | เทียบกับจำนวนที่ฝั่งลูกค้าบอกว่าส่งมา |
| Customers created automatically | ลูกค้าที่ระบบสร้างให้เอง เพราะ `customer_id` ยังไม่เคยมี | ปกติสำหรับลูกค้าใหม่ ถ้าเยอะผิดปกติ ฝั่งลูกค้าอาจส่ง `customer_id` เปลี่ยนไปทุกครั้ง |
| Same conversation under different ids | บทสนทนาเดียวกันแต่ส่งมาด้วย `id` ต่างกัน | ฝั่งลูกค้าน่าจะสร้าง `id` ใหม่ทุกครั้งที่ส่งซ้ำ ต้องใช้ `id` เดิมของห้องแชต |
| Pending, still within N min | รอ AI อยู่ ยังไม่เกินเวลา | ปกติ รอแล้วรันใหม่ |
| Pending longer than N min (stuck) | รอ AI นานเกินไป | เช็กว่าบอตรันอยู่ (`/health`) และดูคิวที่ `GET /api/queue/status` |
| Triage failed | AI วิเคราะห์ไม่สำเร็จ | ดู log ของบอตตาม id แล้วสั่งวิเคราะห์ใหม่ได้ที่ `POST /api/chats/:id/triage` |
| Not analysed: quota exceeded | โควตาของบริษัทเต็ม | เพิ่มโควตาหรือเปลี่ยนแพ็กเกจ |
| Completed but result missing | สถานะเสร็จแล้ว แต่ไม่มีหมวด สรุป หรือรายการปัญหา | ดูแชตนั้นใน Back Office แล้วสั่งวิเคราะห์ใหม่ |

บรรทัดสุดท้ายจะบอก `All good` หรือ `Needs a look: N item(s)`
exit code เป็น `0` เมื่อไม่มีปัญหา, `2` เมื่อมีรายการที่ต้องดู และ `1` เมื่อรันไม่ได้ เช่น หาบริษัทไม่เจอ

**ข้อจำกัด:** ส่ง `id` เดิมซ้ำจะอัปเดตแถวเดิม และตาราง `chats` ไม่มีเวลาอัปเดต จึงนับไม่ได้ว่าแต่ละห้องถูกส่งซ้ำกี่ครั้ง
แชตเก่าที่ถูกส่งซ้ำแล้วยังค้างหรือล้ม จะยังแสดงในหัวข้อ pending / failed แต่ไม่นับใน Chats received

## ขั้นตอนทดสอบกับ OneBoxx (วันศุกร์)

1. **ก่อนเริ่ม:** เช็กว่าบอตรันอยู่ `GET /health` และบริษัทมีแพ็กเกจ `active`
2. **รันครั้งแรก** เพื่อดูค่าก่อนเริ่ม

   ```bash
   node scripts/checkIngest.js --company "<ชื่อบริษัท>" --since 1h
   ```

3. **ให้ OneBoxx ส่งแชตทดสอบ** หรือส่งเองด้วย [Postman collection](sift-ai-ingest.postman_collection.json) (ดูวิธีใน [curl-examples.md](curl-examples.md))
4. **รันทันทีหลังส่ง:** แชตควรขึ้นใน `Chats received` และอยู่ในหัวข้อ `Pending, still within ...`
5. **รอ 1-2 นาทีแล้วรันอีกครั้ง:** แชตควรเป็น `completed` ทั้งหมด และไม่มีหัวข้อที่ต้องดู
6. **ส่งห้องเดิมซ้ำโดยไม่แก้ข้อความ:** response ต้องได้ `"triage_queued": false` และจำนวนแชตไม่เพิ่ม
7. ถ้าเจอ `Same conversation under different ids` ให้แจ้ง OneBoxx ว่าต้องใช้ `id` เดิมของห้องแชตทุกครั้ง

### ผลตอนลองกับบริษัทชั่วคราว (25/11)

ส่ง request 1-6 ของ Postman collection แล้วส่งบทสนทนาของ request 2 ซ้ำด้วย `id` ใหม่อีกครั้ง

- request ทั้ง 6 ได้ status ตามที่คาด (200, 200, 200, 400, 401, 401)
- รันทันทีหลังส่ง: `Chats received: 3` ทั้งหมดอยู่ใน `Pending, still within 10 min` และเจอ `Same conversation under different ids: 1`
- AI วิเคราะห์ครบ 3 แชตใน 73 วินาที รันอีกครั้งได้ `completed: 3` และไม่มีแชตที่ผลหาย
- ส่ง request 3 ซ้ำโดยไม่แก้ ได้ `triage_queued=false`
- ลบบริษัทชั่วคราวและข้อมูลทั้งหมดแล้ว
